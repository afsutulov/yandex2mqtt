## Что проверяют тесты

- Discovery и изоляция пользователей; чужие и неизвестные ID в query/action.
- Отсутствие MQTT-публикации при запрете доступа.
- Правильное wire-преобразование bool ↔ 0/1; чувствительность топиков к регистру.
- Обновление нескольких устройств из одного state-топика.
- Отказ от выдуманного начального состояния и маскировки некорректных данных.
- Ошибки функции/значения/публикации; malformed JSON, отсутствующие массивы.
- Отсутствие оптимистичной подмены состояния значением команды.
- Ожидание свежего подтверждения, обработка быстрого MQTT-эха, timeout занятого устройства.
- Range bounds/precision, relative range, mode enumeration, HSV, повторные event-события.
- Полный browser OAuth flow: форма входа, CSRF, новая сессия, согласие, redirect, state.
- PKCE mismatch, replay кода, истечение кода, неизвестный код, неверный клиент.
- Refresh-ротация и одноразовость при конкурентных запросах.
- Сохранение токенов между открытиями файла, отсутствие сырых токенов, Unix-права 0600.
- Отзыв access/refresh при unlink; независимость другого OAuth-клиента.
- Клиентский токен не даёт доступа к пользовательским устройствам.
- ACL/актуальная привязка для callback, повтор после HTTP 503, прекращение после unlink.
- Отказ записи токена при недоступном файле; миграция паролей и защита от перезаписи конфига.
- Одновременные MQTT-update/query под race detector.

## MQTT-интеграция

В тесте используется самостоятельный TCP-брокер **Mochi MQTT v2.7.9**,
а не mock функций Publish/Subscribe. Он запускается на loopback и используется
только в тестах; в рабочем бинарнике MQTT-брокера нет.

1. Брокер заранее хранит retained state `0`.
2. Go-мост подключается и получает сохранённое состояние.
3. Отдельный MQTT-клиент имитирует устройство: получает команду `1` и публикует state `1`.
4. Мост подтверждает команду после реального MQTT-state и выдаёт bool `true`.
5. Брокер выключается; команда при отключении возвращает ошибку.
6. Новый брокер запускается на том же адресе с retained state `0`.
7. Мост переподключается, восстанавливает подписки и получает новое состояние.

## Что не проверено в этой среде

- Подключение к реальному навыку/аккаунту Яндекса и callback на dialogs.yandex.net.
- Переключение физических светильников, розеток, датчиков пользователя.
- TLS/учётные данные конкретного MQTT-брокера и сертификат публичного домена.
- Выполнение готовых Windows, macOS и Linux arm64 программ: они проверены сборкой.
- Сборка/запуск Docker и запуск unit в systemd: файловые инструкции подготовлены,
  но Docker и systemd-службы в среде разработки не запускались.
- Нагрузочное тестирование больших потоков измерений/многих одновременных пользователей.

Перед эксплуатацией: заполните свой конфиг, выполните `-check`, проверьте привязку
в Яндексе, получение state и физическое исполнение одной команды каждого типа.
Порядок настройки и ограничения подтверждения команд описаны в README.md.
