# Анализ исходного проекта и исправления

Основание: публичные исходники [alvlapo/yandex2mqtt](https://gitverse.ru/alvlapo/yandex2mqtt),
коммит **d26960b8fcc34ba0f4cc6f62114e957b3cc0f0f3**. Изучены app/device/config,
auth, все db/routes/utils, загрузчики устройств, шаблоны входа/согласия/аккаунта,
README, package.json и LICENSE. Проверка выполнена 03.10.2026.
Ссылки и номера строк ниже относятся к этому коммиту оригинала.

## Общий вывод

Оригинал — небольшой Node.js OAuth-сервер с MQTT-мостом, пользовательским доступом
к устройствам и API уведомлений. Основная схема пригодна для переноса, но реализация
содержит реальные ошибки управления, обработки данных и разграничения доступа.
Конфигурация из комплекта не соответствует коду запуска. Оригинал не запускался
против реального Яндекса; выводы об ошибках основаны на конкретных ветвях исходников.

Go-версия сохраняет назначение, основные URL, модель устройств и mappings.
Это самостоятельная реализация с исправленным поведением, а не обёртка над Node.js.

## Дополнительные изменения

- Обработка запросов и состояния защищена от гонок; отдельная очередь команд устройства
  сохраняет последовательность и учитывает deadline ожидания.
- Добавлены range/mode/toggle/color и проверка bounds/enumeration, относительные range-команды.
- При reconnect входящие состояния сбрасываются, чтобы не выдавать старый кэш как свежий.
- API bearer-аутентификация не создаёт браузерную сессию.
- Оригинальные основные URL сохранены; добавлены `/v1.0/...` для endpoint без `/provider`.
- Учётные данные MQTT/уведомлений остаются в приватном config.json: конфиг нужно защищать.
- Legacy OAuth grants включаются явно; основной code + refresh используется по умолчанию.
- Go >=1.26, зависимости зафиксированы go.mod/go.sum и включены в vendor.
- Node/npm/Loki не нужны для обычной работы; журналы — JSON в stdout для systemd/Docker.

## Что изменится при переходе

1. Потребуется заново привязать аккаунт: старые OAuth-токены/Loki не импортируются.
2. Config.js переносится через экспорт и миграцию. Пользовательские пароли после
   миграции продолжают подходить, но в файле остаются их bcrypt-хеши.
3. Некорректные значения и недоступные функции теперь возвращают ошибку вместо DONE/0.
4. До MQTT-state устройство с неизвестными retrievable-параметрами отображается недоступным.
5. OAuth redirect должен быть зарегистрирован. Для Яндекса адрес добавляется миграцией.
6. Для уведомлений нужно reportable=true; миграция включает его у функций со state-binding.
7. Формы входа и согласия оформлены заново средствами Go html/template;
   веб-редактора конфига нет — в оригинале его также не было.

## Границы проверки

Проверены Go-реализация, протокол MQTT с самостоятельным брокером и формат HTTP/OAuth
в локальных тестах. Без пользовательского навыка, токенов и физических устройств
невозможно подтвердить реальную привязку к Алисе, TLS вашего домена и физическую
реакцию оборудования. Эти сценарии требуют приёмочной проверки после настройки.

Это аудит прикладного исходного кода, а не полный аудит безопасности сети,
сертификатов, брокера, ОС и цепочки поставки первоначальных npm-зависимостей.
